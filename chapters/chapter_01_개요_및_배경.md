# Chapter 01: NASA "Power of 10" 개요 및 배경

## 1.1 NASA와 소프트웨어 안전성

우주선은 수억 달러의 비용과 사람의 생명이 걸린 프로젝트입니다. 하나의 소프트웨어 버그로 인해 임무가 실패하거나 우주비행사의 생명이 위험해질 수 있습니다.

### 역사적 사례: 아리안 5호 (Aristotle 5)

1996년 6월 4일, 유럽 우주국(ESA)의 아리안 5호 로켓은 첫 비행에서 발사 37초 만에 폭발했습니다. 원인은 **정수형 변환 오류(integer conversion error)**였습니다. 64비트 정수를 16비트 정수로 변환하면서 발생한 오버플로우가 비행 제어 시스템을 완전히 무력화시켰습니다.

이 사고는 소프트웨어 검증의 중요성을 전 세계에 각인시켰습니다.

## 1.2 Power of 10의 탄생

- **제정자**: Gerard J. Holzmann (제트 추진 연구소, JPL)
- **시기**: 2000년대 초반
- **목적**: 코드 리뷰와 정적 분석을 방해하는 코딩 관행 제거를 통한 치명적 소프트웨어 오류 예방
- **대상 언어**: C 프로그래밍 언어 (특히 우주선 임무 관련 시스템)

## 1.3 왜 "10"인가?

이 규칙들은 총 10개의 간결하고 검증 가능한 지침으로 구성됩니다. 각 규칙은:

- **단순함**:理解和记忆하기 쉬움
- **검증 가능성**: 정적 분석 도구로 자동 검증 가능
- **실용성**: 실제 코드 리뷰에 즉시 적용 가능

## 1.4 핵심 철학

```
단순성 > 복잡성
예측 가능성 > 유연성
명확성 > 간결함
안전성 > 성능
```

## 1.5 이 교육 자료에서 다룰 주요 논점

1. NASA의 "Power of 10" 규칙들은 우주선 "안전벨트"
2. 복잡한 흐름 구조 (Goto, 재귀)는 피하라
3. 모든 루프에는 고정된 반복 한계가 있어야 한다
4. 초기화 이후 동적 메모리 할당 금지
5. 데이터 객체는 가장 좁은 범위에서 선언할 것
6. 반환값 확인 및 매개변수 검증
7. C언어 전처리기 사용 제한
8. 포인터 사용 제한
9. 모든 가능한 컴파일 경고를 활성화하고 해결할 것
10. 논평: 균형잡힌 적용의 중요성
